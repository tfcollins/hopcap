# hopcap on the ADRV9361-Z7035 (`lablp`): timed RX and TX FastLock hops

Status: approved by the owner 2026-11-25 (decisions 1-5 below). Builds on tick
`feat/adrv9361z7035-tick` (Tick on the Z7035) and vrt49's `adrv9361z7035_vrt49_sfp`
1G SFP design. Open PRs only; nothing is merged by the implementer.

## Goal

Port the hopcap composite (Tick fires hops, the hop controller gates capture and
stamps the hop frequency into VITA 49.2 Context packets, data leaves over vrt49) from
the ADRV9009-ZU11EG to the ADRV9361-Z7035, hop **both RX and TX**, and prove on
hardware that RX hops and TX hops land on the Tick timestamps they were scheduled for.

## Decisions (owner-approved)

1. **FastLock pin select.** Tick `gpio_out[2:0]` drives AD9361 `CTRL_IN[3:1]` directly
   (corrected 2026-11-25: the first hardware run showed the profile comes from CTRL_IN1..3,
   although UG-570/671 say CTRL_IN0..2)
   (IOB registers on the tick clock). UG-671: 0x25A D1 makes CTRL_IN0..2 select the Rx
   fast lock profile; 0x29A is identical for Tx. With both enabled, one 3-bit code
   selects RX profile k and TX profile k together: **slot k = (rx_lo_k, tx_lo_k)**, at
   most 8 slots. No full retune, no SPI in the timed path.
2. **hopcap's HOP2 controller** (`hdl/vrt49_fhm_hop_ctrl`) gates and stamps; it never
   drives the radio. vrt49's HOP1 `vrt49_ad9361_hop_ctrl` is removed from the build.
3. **VRT time = Tick time.** An internal 1 Hz pulse generated on the tick clock
   (`tick_pps_gen`) drives both Tick `pps_in` and `vrt49_time_base`; the host loads Tick
   `TIME_EPOCH = N * TIME_TICK_HZ` and the framer seconds `N` for the same PPS edge, so a
   VRT timestamp and a Tick tick count describe the same clock. No GPS.
4. **The SD card is never written.** lablp boots stock Kuiper; the hopcap bitstream is
   loaded at runtime through the FPGA manager (same flow as tick's
   `lablp_tick_runtime_load.sh`), the AD9517 OUT4 is set to 125 MHz through IIO for the
   SFP, and a power cycle restores stock.
5. Hop tests at 15.36 MSPS, one RX channel, **no frame throttling**
   (`FORWARD_EVERY_N 1`; about 0.5 Gb/s on the 1G link). CI on the nemo runner; the SFP
   is cabled to nemo `enp7s0` (192.168.2.10/24).

## Hardware composition

Base: vrt49 `hdl/projects/adrv9361z7035_vrt49_sfp` at the pinned vrt49 revision. The
hopcap fragment `hdl/system_bd_adrv9361_hop.tcl` runs after vrt49's `system_bd.tcl` body
and before `validate_bd_design`:

- delete vrt49's `tick_scheduler_0`, `vrt49_hop_ctrl_0` (HOP1) and the
  `ad9361_fastlock_select` port;
- source Tick's own fragment from `third_party/tick`
  (`hdl/projects/adrv9361z7035/ccfmc_lvds/tick_adrv9361z7035_ccfmc_lvds.tcl`): scheduler
  at 0x44AA0000, 50 MHz PL clock from FCLK0 behind an async AXI-Lite converter, ports
  `tick_clk` and `tick_ctrl_in[2:0]`. **Tick at 50 MHz is required**: with retained-slot
  repeats the scheduler misses 100 MHz on the Z7035 -2L (see tick
  `docs/adrv9361z7035-tick.md`). The scheduler RTL comes from `third_party/tick`, the same
  revision whose driver hopcap builds;
- HOP2 at 0x44AB0000 on `sys_cpu_clk` (100 MHz). Its `scheduler_gpio` is
  `{gpio_out[2:0], gpio_out[3]}` (bit 0 = event, bits 3:1 = slot) through hopcap's
  `tick_gpio_sync` (slot two flops, event three), constrained like the timed-dma profile;
- `vrt49_time_base_0` on the AD9361 data clock (`util_ad9361_divclk`), `sample_valid`
  from the tap's `packed_fifo_wr_en`, `pps_in` from `tick_pps_gen`; framer `tb_*`/
  `tb_tuple_*` wired as on the ZU11EG; CDC constraints for the PPS, config bus and tuple;
- `vrt49_link_throttle` `FORWARD_EVERY_N 1`.

`system_top.v` (vrt49 already splits the AD9361 EMIO buffer): replace
`assign gpio_ctl[2:0] = ad9361_fastlock_select` (moved to `gpio_ctl[3:1]`) with Tick's IOB-register + `ad_iobuf`
block (EMIO 43:41 read the pins back) and wire `tick_clk`/`tick_ctrl_in`.

## Software

- **Bit map:** a hop to slot k is two Tick GPIO_WRITEs: rise `mask 0xF, value 0x8|k`
  (CTRL_IN and the controller slot change on the same tick as the event), fall
  `mask 0x8, value 0` a pulse later. All hops of a plan (≤ 8 + edges) can be queued up
  front; no Talise one-behind staging and no priming edge.
- **Units:** plans are in microseconds. Tick ticks = µs × 50; controller SETTLE/CAPTURE/
  DRAIN_TIMEOUT = µs × 100. Never mix them.
- **FastLock bank** (replaces the Talise stager): with pin control off, for each slot set
  RX LO then `fastlock_store k` (altvoltage0) and TX LO then `fastlock_store k`
  (altvoltage1); recall profile 0 on both; enable pin select (0x25A/0x29A D1|D0) and park
  Tick CTRL_IN at 0. The driver's cached LO readback is not evidence of a pin recall.
- **Receiver:** nemo `enp7s0`, the framer streams to 192.168.2.10; an RX buffer on
  `cf-ad9361-lpc` is held open during the run so the tap sees samples.

## Proof on hardware

TX1 → RX1 couples strongly on lablp (a 1 MHz DDS tone reads 95 dB above the floor; moving
only the TX LO by 1 MHz moves it exactly). With TX transmitting a DDS tone `f_dds`, the
tone in RX baseband sits at `(tx_lo_k - rx_lo_k) + f_dds`. The slot table makes that
offset different for every consecutive pair and includes:

- **TX-only hops** (rx_lo equal, tx_lo different): the tone moves only because TX hopped;
- **RX-only hops** (tx_lo equal, rx_lo different);
- **both** hops.

For each hop the test finds the first sample where the tone sits at the new offset
(short-time frequency estimate on the captured IQ), converts that sample's VRT timestamp
to Tick time, and compares it with the hop's EXECUTED Tick timestamp. The difference is a
fixed latency (pin sampling, PLL settle, digital pipeline). It is pinned per image with a
tolerance, must agree for RX-only, TX-only and both hops, and is checked across two boots
(sdk#41 showed a per-boot shift elsewhere). Also required: Tick EXECUTED with zero skew,
Context frequency = the slot's RX LO, epochs strictly increasing, no superseded events, a
locked time base, and a no-edge control (no Tick command → tone and epoch unchanged).
